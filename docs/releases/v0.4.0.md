# NEXUS AI v0.4.0: enterprise RAG & document intelligence (portfolio release)

**Status: prepared for tagging.** The tag `v0.4.0` and the GitHub Release are created from `main`
only after the owner's explicit approval (checklist at the end). NEXUS AI is a
portfolio-grade system with synthetic data: hardened and tested, **not** production-ready,
certified or externally penetration-tested. License: MIT for the project's own code
([LICENSE](../../LICENSE)); third-party terms in [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).

v0.4.0 is the first version proposed for a tag. It contains Phases 1–4 (merged into `main` through
PR #2; v0.3.0 was a release candidate that was never tagged separately) and the Phase 5
documentation, the recorded English product demo and one frontend fix.

**Demo video:** [`docs/videos/nexus-ai-demo.mp4`](../videos/nexus-ai-demo.mp4) (2:25, 1920 × 1080,
H.264, no audio, English on-screen captions): Keycloak SSO, document upload and background
ingestion, invoice extraction and OCR, human-in-the-loop review, a blocked approval caused by a
validation failure, hybrid RAG with grounded citations, multi-tenant isolation, evaluation and
Grafana. It is an automated recording of the real local stack with synthetic data; nothing is mocked.

| Phase | Scope |
|---|---|
| 1. MVP | FastAPI + React, upload, chunking, BM25, document-level ACL, extractive answers with `[S#]` citations, audit |
| 2. Hybrid RAG | PostgreSQL FTS + pgvector (`multilingual-e5-small`), Reciprocal Rank Fusion, four retrieval modes with the ACL inside every statement, calibrated abstention, 100-question evaluation, CI gates |
| 3. Document intelligence | layout-aware parsing (text / scanned / mixed PDF, DOCX, XLSX, TXT, MD), Tesseract OCR with deskew and lattice tables, contract and invoice schemas with verbatim evidence, grounding, Decimal validation, human review, multi-document comparison, 32-document evaluation |
| 4. Enterprise hardening | OIDC (Keycloak, PKCE, BFF), PostgreSQL FORCE RLS, durable PostgreSQL job queue and workers, S3 / MinIO storage with document lifecycle, JSON logs, Prometheus, Grafana, OpenTelemetry; security, failure-injection, backup / restore and load verification |
| 5. Portfolio release | README, architecture overview, demo guide with real screenshots, recorded English demo video, evaluation summary, case study, portfolio texts, these notes; package metadata aligned to 0.4.0; tenant breadcrumb fix |

## Installation

```bash
git clone https://github.com/KrzakLara/nexus-ai-enterprise-rag.git
cd nexus-ai-enterprise-rag
docker compose -f compose.yaml -f compose.oidc.yaml -f compose.observability.yaml up --build -d
curl -s localhost:8000/api/health/ready
```

Open http://localhost:5173 → **Sign in with SSO** → `finance@northstar.demo` / `DemoPass123!`
(synthetic, local only). Walk-through: [DEMO.md](../DEMO.md). Running without Docker, tests and
evaluation: [TECHNICAL_REFERENCE.md](../TECHNICAL_REFERENCE.md).

## Known limitations

- Synthetic, self-authored datasets; scores are optimistic for real documents.
- No live LLM answer or extraction evaluation.
- Exact vector scan without ANN; no reranker; `simple` FTS without stemming; cross-language
  retrieval is the weakest category.
- Load figures come from one laptop (one API and one worker container, CPU embeddings); under the
  stress profile, hybrid question latency p95 reached ~18.8 s and 3.5 % of requests were shed with 503.
- No external penetration test, compliance certification, HA / multi-region, WAF or KMS.
- The manual `load-test.yml` workflow has not been run on GitHub (the k6 smoke profile runs in CI).
