# NEXUS AI v0.3.0 (release candidate): enterprise hybrid RAG + document intelligence

**Status: release candidate on `feat/phase3-document-intelligence`. Not tagged and not released yet.** This is a local demo, not production-ready. All data is synthetic. License: MIT for the project's own code ([LICENSE](../../LICENSE)); third-party terms are listed in [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).

v0.3.0 contains three phases:

| Phase | Scope |
|---|---|
| **1. MVP** | FastAPI + React, demo JWT auth, PDF/DOCX/TXT upload, chunking, BM25, document-level ACL, extractive answers with `[S#]` citations, audit trail |
| **2. Advanced hybrid RAG** | PostgreSQL + pgvector (`multilingual-e5-small`), PostgreSQL full-text search, Reciprocal Rank Fusion, four retrieval modes with the ACL inside every SQL statement, a 100-question evaluation with bootstrap CIs, calibrated abstention, CI gates |
| **3. Document intelligence** (new) | layout-aware parsing (text / scanned / mixed PDF, DOCX, XLSX, TXT, MD); Tesseract OCR (eng + hrv) with deskew and table-lattice reconstruction; contract and invoice schemas with verbatim evidence per field; grounding and Decimal validation; human review with optimistic locking and audit; multi-document comparison and questions; a frozen 32-document evaluation with CI gates |

## Architecture in brief

A modular monolith: FastAPI with sync routes running in the threadpool, PostgreSQL 16 + pgvector, React/TypeScript, Docker Compose.
- Document intelligence lives in `backend/app/docintel/` and shares **one ACL** (`security.authorized_documents`), one audit trail and one database with the RAG.
- Alembic `0004` adds five tables and changes none.
- The new parser feeds the unchanged Phase 2 chunker, so retrieval, chunk IDs and citations keep their meaning.
- Details: [architecture.md](../architecture.md) (ADR-013), [document-intelligence.md](../document-intelligence.md), [human-review.md](../human-review.md), [security.md](../security.md).

## Known limitations

- **Evaluation data:** both corpora are **synthetic** and written by the project. The Phase 3 labels were AI-spot-checked, **not independently human-verified** ([checklist](../ground-truth-review-checklist.md)). The test split includes label wordings the rules do not know, and those misses are reported, not patched.
- **OCR:** the scans are clean simulations, so real office scans will do worse. Layout is single-column. There is no handwriting, stamp or signature handling.
- **LLM extraction:** live behaviour is **not verified** (no API key). The optional provider is tested only against a fake client.
- **Deployment:** demo authentication (no OIDC, no rate limiting), no PostgreSQL row-level security, no background workers or object storage, and the frontend container runs the Vite development server. These are Phase 4 items.

## Reproduce

```bash
git clone https://github.com/KrzakLara/nexus-ai-enterprise-rag && cd nexus-ai-enterprise-rag
docker compose up --build                       # http://localhost:5173 · password DemoPass123!
python scripts/demo_scenarios.py                # 9 PASS, 1 KNOWN
python scripts/build_docintel_dataset.py --check   # frozen corpus unchanged

# tests and gates inside the API image (Tesseract included); the *_test / *_eval databases are dropped and re-created
docker compose up -d db
docker compose run --rm --no-deps -v "$PWD:/src" -w /src -e PYTHONPATH=/src \
  -e TEST_DATABASE_URL=postgresql+psycopg://nexus:demo_local_only@db:5432/nexus_test --entrypoint "" api \
  sh -c "uv sync --locked --extra dev --inexact && python -m pytest -q \
         && python scripts/evaluate.py --ci --database-url postgresql+psycopg://nexus:demo_local_only@db:5432/nexus_eval \
         && python scripts/evaluate_docintel.py --ci --database-url postgresql+psycopg://nexus:demo_local_only@db:5432/nexus_docintel_eval"
```
