# Document-intelligence evaluation: methodology

The numbers are generated by `scripts/evaluate_docintel.py` into [extraction-evaluation-results.md](extraction-evaluation-results.md) and `eval/docintel/reports/latest.json`. This page explains what they mean and what they do **not** show.

## Corpus (`eval/docintel/`, frozen)

32 fictional documents, generated once by `scripts/build_docintel_dataset.py` and committed with SHA-256 hashes in `manifest.json`. **Dataset version 1.1:** three label errata (exponent-notation numbers, two names for one jurisdiction, and a new `value_period` field) are documented in [`eval/docintel/ERRATA.md`](../eval/docintel/ERRATA.md). The source documents are unchanged, and the v1.0 labels and report are archived in `eval/docintel/reports/archive/`. Evaluation and tests refuse to run on a modified file. A rebuild on the same platform is byte-identical.

| | |
|---|---|
| Types | 16 contracts, 14 invoices, 2 other (meeting minutes, internal policy) |
| Formats | 10 text PDF, 7 scanned PDF (10 scanned pages), 1 mixed PDF (text + scanned page), 4 DOCX, 3 XLSX, 4 TXT, 3 Markdown |
| Languages | 20 English, 12 Croatian (diacritics, decimal commas, `31. ožujka 2026.`) |
| Tenants | Northstar and Otherco, with group grants (procurement, finance, legal) |
| Hard cases | multi-page contracts with section headings and schedule tables; vertically merged table cells; a contract amendment with the same ID and different terms; two "End date" lines in one contract; a supplier whose IBAN differs between two invoices; missing fields (no IBAN, no value, no expiration); invalid invoices (wrong subtotal, wrong line amount, wrong total, due date before issue date); multi-rate VAT; 0 % VAT in USD; aligned plain-text tables |
| Split | 18 **dev** documents (used while writing the rules) / 14 **test** documents (not used for rule development; several deliberately use wordings the rules do not know: *Najmoprimac*, *Consultant*, *Payment*, *Iznos za uplatu*) |

### Ground truth

**The labels are the authored parameters from which each document was rendered** (`backend/evaluation/docintel_corpus.py`): invoice numbers, dates, line items, parties, terms. They are written by hand, and **no label is derived from any extractor output**.
- Amounts are computed from line items with Decimal and ROUND_HALF_UP. Deliberate errors are injected as explicit perturbations, and the codes the document should trigger are listed in `expected_errors`.
- Each labelled field is tagged on the element that prints it, so its ground-truth page is a layout fact.
- The OCR ground truth is the exact text drawn on each scanned page.
- `tests/test_docintel_eval.py` checks that every labelled value has a ground-truth page and that the corpus covers the required formats, languages, tenants and error cases.

**Caveat:** the labels were authored by the same team that wrote the extractor, and a person has not independently re-verified them. A human spot-check is recommended before treating the numbers as more than a regression benchmark.

### Scanned pages

Scans are rendered at 200 dpi with the DejaVu Sans font, a random rotation of up to ±0.8°, Gaussian blur, Gaussian noise and JPEG compression at quality 72, and stored as image-only PDFs (no text layer). They are clean compared with real office scans: no stamps, handwriting, folds, shadows or low-contrast faxes. **The OCR numbers are therefore an upper bound** for real documents.

## Pipeline under test

For every document, the owner uploads it through the real API into a fresh PostgreSQL database (Alembic migrations). The pipeline then runs: format detection → parsing (Tesseract 5 OCR where needed) → classification → offline rules extraction → grounding → validation → persistence. The evaluation reads back the **persisted** extraction and structure through the API. Embedding on upload is switched off because retrieval is evaluated separately (Phase 2).

## Metrics

| Group | Metric | Definition |
|---|---|---|
| Extraction | exact match, precision, recall, F1 | Over field slots: the scalar fields of each document type, plus every ground-truth party, plus extra predicted parties. TP = predicted value equals the ground truth. A **wrong** value counts as both FP and FN. Text is compared case- and whitespace-insensitively without trailing punctuation, numbers by value, everything else exactly. Reported per split, type, language, format and field. |
| | missing-field detection | ground-truth-empty fields left empty / all ground-truth-empty fields; plus the count of invented values |
| | unknown documents | number of fields extracted from documents that are neither contract nor invoice (should be 0) |
| Classification | accuracy, confusion matrix | `unknown` is a class |
| Evidence | reference validity | the cited document is right, the page exists, and the text is on that page (and no evidence error was raised) |
| | support rate / unsupported-field rate | grounding `exact` or `normalized` / everything else |
| | page attribution | evidence page = ground-truth page of the field |
| Tables | cell association accuracy | line-item cells (row × column) equal to the ground truth |
| | line-item exact match | rows with all 5 cells correct; plus extra predicted rows |
| Validation | invalid-field detection P / R | arithmetic, date and IBAN error codes found versus `expected_errors` |
| | numeric reconciliation accuracy | invoices whose checks fail exactly when the ground truth says the document is invalid |
| OCR | CER, WER | Levenshtein distance / reference length on whitespace-normalized text |
| | key-token recall | share of the reference's numeric and identifier tokens (amounts, dates, IDs, IBAN groups) found verbatim, i.e. completeness for business values |
| Review | correction rate | corrections a careful reviewer had to make / field slots |
| | approval consistency | approved extractions whose final values equal the ground truth |
| | validation false-accept rate | invalid documents (by ground truth) that validation let through to approval |
| | errors not flagged | extractions with at least one wrong field that still had status `pending` |
| | optimistic lock | a stale `expected_version` is refused with HTTP 409 |
| Multi-document | precision / recall / exact | query results vs answers computed from the ground truth and an **independent ACL oracle**, before and after review (rejected documents excluded after review) |
| Security | violation counts | see below; every violation count must be 0 |

### Security matrix

For each of 7 personas and each of 32 documents:
- **Reads:** GET extraction, structure, processing, history and field evidence. A persona not authorized by the oracle must get 404.
- **Writes:** PATCH fields, approve, reject and process by every non-reviewer and every unauthorized persona. The expected answers are 404 (unauthorized) and 403 (authorized, not a reviewer).
- **Comparisons:** one authorized plus one forbidden document must give the generic 404, with neither the ID nor the title of the forbidden document in the response.
- **Queries and library listing:** must not contain any document the persona may not read, or any document from another tenant.

The oracle re-implements the ACL rule in Python. It does not use the application's SQL.

## Separation of providers

Only the deterministic **offline rules provider** is measured. The optional **LLM provider is NOT VERIFIED**: there is no API key here. Its contract is tested with a fake client in `test_docintel_llm.py`. The report states this explicitly, and no LLM number is published.

## CI regression gates

`python scripts/evaluate_docintel.py --ci` (GitHub Actions, with Tesseract installed from Ubuntu packages) fails on any of:
- an authorization violation;
- a document that is not processed;
- an invalid document that validation lets through;
- a stale review edit that is not refused;
- a metric below `eval/docintel/ci_thresholds.json`.

The floors are the measured values minus about one document or field; the justification is in the file. A test checks that every floor stays at or below the measured value.

## Reproduce

```bash
docker compose up -d db
docker compose run --rm --no-deps -v "$PWD:/src" -w /src -e PYTHONPATH=/src --entrypoint "" api \
  sh -c "uv sync --locked --extra dev --inexact && python scripts/evaluate_docintel.py \
         --database-url postgresql+psycopg://nexus:demo_local_only@db:5432/nexus_docintel_eval"
# or, with Tesseract (eng + hrv) installed locally:
python scripts/evaluate_docintel.py --database-url postgresql+psycopg://nexus:demo_local_only@127.0.0.1:5433/nexus_docintel_eval
python scripts/build_docintel_dataset.py --check   # the frozen corpus is unchanged
```
